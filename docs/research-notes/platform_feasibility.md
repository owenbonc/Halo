# Platform feasibility: what a third-party scam-detection app can observe and do (iOS, Android, browsers, email, messaging, telephony, LLM, alerts)

All sources accessed 2026-10-23. Apple pages were read through Apple's documentation JSON (`developer.apple.com/tutorials/data/documentation/...json`) because the HTML pages render client-side; the cited URLs are the human-readable equivalents. "Verified" means the claim is in the cited official page. "Uncertain — needs spike" means the docs were ambiguous, did not render, or I could not find them.

Context seen in the docs: Apple docs now list iOS 27.x APIs (e.g. LiveAssistance "introducedAt 27.2"), and Apple's SystemLanguageModel page lists an iOS 27.0 model version. Gemini API docs show current model ids such as `gemini-3.8-flash`. Treat model and OS version names as of 2026-10-23.

## Q1. For each channel and platform: what can be observed, via which supported API or user action, real-time vs delayed, what fails, and what store policies forbid?

### Takeaway
Neither mobile OS lets a third-party app hear or transcribe live cellular call audio, and neither lets it read iMessage or WhatsApp content. On iOS a third-party app sees only phone numbers (Call Directory, Live Caller ID Lookup) and the text of SMS/MMS from unknown senders (Message Filter). Android gives more: call metadata in real time through the call-screening role, plus notification text through a notification listener. Both come with strong Play policy controls, and Android 15 redacts OTPs from notifications that untrusted listeners receive. The only routes that are documented, policy-safe and real-time for call audio and message content are ones where the user acts: forwarding a call to a Twilio number, or sharing, forwarding or screenshotting content to the service. Email works for small groups through Gmail API Testing mode or Microsoft Graph Mail.Read. Production Gmail needs restricted-scope verification plus a CASA assessment.

### Hard blockers (verified)
1. **Live cellular call audio or transcript on Android.** `CAPTURE_AUDIO_OUTPUT` is "Not for use by third-party applications", and Play disallows call recorders. [Android Manifest.permission](https://developer.android.com/reference/android/Manifest.permission); [Play SMS/Call Log policy](https://support.google.com/googleplay/android-developer/answer/10208820)
2. **Live cellular call audio on iOS.** No API found. Live Caller ID Lookup and Call Directory are number-only, and the default dialer gives call initiation and history only. Confidence is high, but this is a negative finding: no doc states "no audio". [Apple Live Caller ID](https://developer.apple.com/documentation/identitylookup/getting-up-to-date-calling-and-blocking-information-for-your-app); [Apple default dialer](https://developer.apple.com/documentation/livecommunicationkit/preparing-your-app-to-be-the-default-dialer-app)
3. **iMessage and contact SMS on iOS.** The Message Filter excludes them explicitly. [Apple SMS/MMS filtering](https://developer.apple.com/documentation/identitylookup/sms-and-mms-message-filtering)
4. **iOS caregiver alert from an SMS filter.** The extension cannot reach the network or write to the shared container, so the app cannot learn about the message. Any alert must originate server-side from the deferred query. Policy acceptability is uncertain. [Apple SMS/MMS filtering](https://developer.apple.com/documentation/identitylookup/sms-and-mms-message-filtering)
5. **Background on-device Gemini Nano on Android.** Blocked: foreground-only. [ML Kit GenAI](https://developers.google.com/ml-kit/genai)
6. **Gemini free tier for UK users.** Not allowed: paid services only. [Gemini API terms](https://ai.google.dev/gemini-api/terms)
7. **Safe Browsing API for a commercial product.** Not allowed: use Web Risk. [Safe Browsing usage](https://developers.google.com/safe-browsing/v4/usage-limits)

### Cited Findings
- On Android, CallScreeningService is bound to "a single app chosen by the user", for incoming calls "prior to ringing" and for outgoing calls. It "must respond to a call within 5 seconds". Only `tel:` calls are passed, and "only calls which are not in the user's contacts are passed for screening, unless the CallScreeningService has been granted Manifest.permission.READ_CONTACTS". Blocked calls are logged with `BLOCK_REASON_CALL_SCREENING_SERVICE`. — [Android: CallScreeningService](https://developer.android.com/reference/android/telecom/CallScreeningService)
- Play lets non-default apps request READ_SMS or READ_CALL_LOG only under listed exceptions, when "there's currently no alternative method to provide the core functionality". The exceptions include "Caller ID, spam detection, and/or spam blocking" and "Anti-SMS phishing", the latter with a track-record requirement. Call recorders are disallowed. Apps without a qualifying declaration may be removed. — [Play: SMS and Call Log permissions](https://support.google.com/googleplay/android-developer/answer/10208820)
- Android 15 adds OTP redaction for untrusted notification listeners, hides notification content during screen sharing, and hides activities of apps posting OTP notifications during screenshare. — [Android 15 behavior changes](https://developer.android.com/about/versions/15/behavior-changes-all)
- Android 15 QPR1+ shows a "large and prominent" status bar chip during media projection and stops projection when the screen locks. — [Android 15 behavior changes](https://developer.android.com/about/versions/15/behavior-changes-all)
- Android 14+ requires consent for each MediaProjection capture session and throws SecurityException if the consent is reused. — [Android 14 behavior changes](https://developer.android.com/about/versions/14/behavior-changes-14); [Android: Media projection](https://developer.android.com/media/grow/media-projection)
- Android 16 in-call protections block granting accessibility and first-time sideloading during calls with non-contacts. The Play Protect disable block applies to Android 6+. A UK banking screen-share warning pilot launched with Monzo, NatWest and Revolut (announced 13 May 2025). — [Google: What's new in Android security and privacy 2025](https://blog.google/security/whats-new-in-android-security-privacy-2025/). Secondary reporting says the pilot later expanded to most major UK banks: [search summary of Google Security Blog/press](https://www.androidauthority.com/new-anti-scam-features-android-show-3556831), not verified on a primary source.
- Google's own Scam Detection in Google Messages runs on-device and covers conversational scams. It is a first-party feature and gives no third-party API. — [Google: What's new in Android security and privacy 2025](https://blog.google/security/whats-new-in-android-security-privacy-2025/)
- Play's accessibility policy lists "antivirus software, automation tools, assistants, monitoring apps…" as not qualifying for `isAccessibilityTool`. Non-tool apps need an in-app prominent disclosure with affirmative consent plus a declaration and a video. "Deceptive and non-declared uses … may result in a suspension". — [Play: AccessibilityService API policy](https://support.google.com/googleplay/android-developer/answer/10964491)
- In iOS 18.2 and later a user may pick a non-Phone app as the default calling app (CallKit or LiveCommunicationKit). A default dialer app needs `com.apple.developer.dialing-app`, and EU-registered accounts and EU-located devices for testing. It "can access the device's conversation history, from the moment your app became the default dialer app." — [Apple: CallKit](https://developer.apple.com/documentation/callkit); [Apple: Preparing your app to be the default dialer app](https://developer.apple.com/documentation/livecommunicationkit/preparing-your-app-to-be-the-default-dialer-app)
- The Call Directory extension specifies identification entries "all at once"; per-call web requests are not possible. — [Apple: Identifying and blocking calls](https://developer.apple.com/documentation/callkit/identifying-and-blocking-calls)
- App Review 2.5.12: call/SMS blocking apps must block only confirmed spam, explain their list criteria, and not use the data for tracking or profiles. — [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)
- Gmail `gmail.readonly` and `gmail.metadata` are restricted scopes. `gmail.addons.current.message.readonly` is sensitive. "If you store restricted scope data on servers (or transmit), then you must go through a security assessment." — [Gmail API scopes](https://developers.google.com/gmail/api/auth/scopes)
- Restricted-scope verification includes a CASA assessment by Google-empanelled assessors, reassessed "at least every 12 months". Exemptions include personal use ("used by only a few users, all of whom are known personally to you") and development or testing projects. — [Restricted scope verification](https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification)
- Microsoft Graph `Mail.Read` delegated: AdminConsentRequired = No, and "available for consent in personal Microsoft accounts". — [Graph permissions reference](https://learn.microsoft.com/en-us/graph/permissions-reference)
- Twilio unidirectional Media Streams deliver inbound and/or outbound audio to a WebSocket. Bidirectional streams use `<Connect><Stream>`. — [Twilio: Media Streams](https://www.twilio.com/docs/voice/media-streams)
- Twilio Real-Time Transcription (`<Start><Transcription statusCallbackUrl=...>`) supports Google and Deepgram engines. Its fork limit is shared with Media Streams, SIPREC and AMD. — [Twilio: `<Transcription>`](https://www.twilio.com/docs/voice/twiml/transcription)

### Inferences
- The only way to show live call analysis honestly is to route the call through infrastructure the product owns (a Twilio number), with the caller and callee aware of it. Present it as "controlled environment / simulation" and never as monitoring of the senior's real calls.
- Android is clearly the richer platform for passive signals: call screening in real time, plus the notification listener for WhatsApp and SMS previews. The iOS story is almost entirely user-initiated sharing plus number and SMS filtering.
- Gmail production access through restricted scopes is a multi-week compliance project. Forwarding to an analysis inbox is the cheapest path to production for email.
- On-device Nano cannot run the background scoring step, so the pipeline needs a cloud LLM. For UK users that means a paid Gemini tier.

### Gaps
- Whether iOS 26/27 Call Screening or Live Voicemail exposes anything to third parties. No API was found in the CallKit, IdentityLookup or LiveCommunicationKit topic lists. The Apple support page did not render.
- A Play policy page specific to NotificationListenerService was not found. Play's stance on a scam-monitoring app that uses notification access is unverified.
- Whether Android restricted settings cover notification-listener access as well as accessibility. The Android Help page cites only accessibility as an example.
- `InCallService`: no audio method was seen in the API list, but no doc says so explicitly.
- Chrome extensions on Android Chrome, Chrome Web Store review rules for reading webmail, and Gmail add-on publishing requirements were not verified.
- Twilio Media Streams codec and sample rate, and Gemini latency figures: no official numbers were extracted.
- The iOS Share Extension doc and the FCM docs were not re-read in detail.

## Q2. What is realistically demoable in three days by a small team, honestly?

### Takeaway
A credible 3-day demo can include the items below, each with a "simulated or controlled" label where it applies:
1. A Twilio-number "scam call" with live transcription, LLM risk scoring and a caregiver push or SMS.
2. An Android build that uses CallScreeningService to flag a seeded number, plus a notification listener that scores WhatsApp or SMS previews.
3. A share-sheet or screenshot upload analysed by Gemini.
4. Gmail in Testing mode, or forward-to-inbox, for email.

Live Caller ID Lookup, Play-approved SMS permissions, CASA and WhatsApp business verification cannot be completed in 3 days.

### Cited Findings
- Twilio Media Streams and Real-Time Transcription give webhooks or WebSocket audio for calls on a Twilio number. — [Twilio: Media Streams](https://www.twilio.com/docs/voice/media-streams); [Twilio: `<Transcription>`](https://www.twilio.com/docs/voice/twiml/transcription)
- UK Twilio numbers need a regulatory bundle with ID and proof of address. Provision the number before the hackathon. — [Twilio: Reading regulations for the UK bundle](https://www.twilio.com/docs/phone-numbers/regulatory/reading-regulations-for-the-uk-bundle) (search snippet only); [Twilio changelog](https://www.twilio.com/en-us/changelog/new-kyc-regulation-for-the-uk-long-codes)
- Gmail Testing mode allows up to 100 test users, with authorizations expiring after 7 days. That is fine for a demo. — [Google Cloud: OAuth publishing status](https://support.google.com/cloud/answer/15549945)
- CallScreeningService needs only the user-granted role. A Play declaration is needed only for Call Log or SMS permissions. — [Android: CallScreeningService](https://developer.android.com/reference/android/telecom/CallScreeningService); [Play SMS/Call Log policy](https://support.google.com/googleplay/android-developer/answer/10208820)
- Expo push wraps FCM and APNs for the caregiver app. — [Expo push overview](https://docs.expo.dev/push-notifications/overview/)
- Gemini accepts inline images and audio (under 20 MB request) and offers a Live API for streaming. — [Gemini API: Audio](https://ai.google.dev/gemini-api/docs/audio); [Gemini Live API](https://ai.google.dev/gemini-api/docs/live)
- Live Caller ID Lookup requires Apple endpoint validation and PIR infrastructure. — [Apple](https://developer.apple.com/documentation/identitylookup/getting-up-to-date-calling-and-blocking-information-for-your-app)

### Inferences
- Recommended demo spine:
  1. A scammer actor calls a Twilio UK number.
  2. Real-time transcription streams to the backend.
  3. An LLM classifies the scam pattern, for example "safe account" or HMRC impersonation.
  4. A caregiver receives a push or SMS with a plain-English summary.

  Then a second beat on the senior's side: share a suspicious SMS or WhatsApp screenshot and get a verdict.
- Android passive pieces (call screening plus notification listener) are worth adding only if someone on the team has native Android experience. Use a sideloaded APK and do not grant permissions during a live call (Android 16 blocks accessibility grants mid-call).
- Do not demo the iOS Message Filter unless it is pre-built. The Associated Domains `messagefilter` setup and Settings enablement add risk.
- Label every simulated input, and avoid any claim of "monitoring calls on iPhone".

### Gaps
- Twilio account and UK bundle approval lead time was not measured. If it is slow, a US or test number is a fallback (unverified).
- WhatsApp Cloud API test-number setup time was not verified.

## Q3. What would require a technical spike to confirm?

### Takeaway
The open items fall into two groups. Platform behaviour: iOS background call-state observation, the iOS Message Filter-to-caregiver path, notification-listener content fidelity (WhatsApp grouping, Android 15 redaction scope), and LLM latency for real-time call scoring. Policy: Play's stance on notification-listener scam monitoring, Apple's stance on server-side alerts from filter queries, and LiveAssistance eligibility.

### Cited Findings
- `CXCallObserver` notifies "any app" of call activity. The behaviour when the app is backgrounded is undocumented. — [Apple: CXCallObserver](https://developer.apple.com/documentation/callkit/cxcallobserver)
- The Message Filter extension cannot access the network or write to shared containers. The system relays to the associated server. — [Apple: SMS and MMS message filtering](https://developer.apple.com/documentation/identitylookup/sms-and-mms-message-filtering)
- Android 15 redacts OTP notifications for untrusted listeners and exempts companion-device apps. — [Android 15 behavior changes](https://developer.android.com/about/versions/15/behavior-changes-all)
- `LiveAssistanceExtension` (iOS 27.2) lets providers join FaceTime calls for "interpreter, captioning, or other services". — [Apple: LiveAssistanceExtension](https://developer.apple.com/documentation/livecommunicationkit/liveassistanceextension)
- ML Kit GenAI is foreground-only, on a limited device list. — [ML Kit GenAI](https://developers.google.com/ml-kit/genai)
- ReplayKit's broadcast picker is deprecated in iOS 27 in favour of ScreenCaptureKit's `SCContentSharingPicker`. — [Apple: RPSystemBroadcastPickerView](https://developer.apple.com/documentation/replaykit/rpsystembroadcastpickerview)
- The Foundation Models framework (iOS 26+) needs an Apple Intelligence-capable device and region. — [Apple: SystemLanguageModel](https://developer.apple.com/documentation/foundationmodels/systemlanguagemodel)

### Inferences
Spike list, in priority order:
1. **Twilio end-to-end latency.** Measure call audio → transcription → LLM verdict → caregiver push, using the Real-Time Transcription webhook versus Media Streams plus the Gemini Live API. Target: an alert before the victim acts.
2. **Notification listener on Android 15/16 with WhatsApp.** Find out how much message text is visible (grouping, "n new messages", redaction) and whether restricted settings block a sideloaded build.
3. **iOS Message Filter.** Can the associated server legitimately alert a caregiver from a deferred query? Check against App Review 2.5.12, which bans using the data "for any purpose not directly related to operating or improving your app".
4. **CXCallObserver.** Is it delivered in the background (it would drive a "you're on a call, be careful" nudge)?
5. **Play policy pre-check.** Can a scam-monitoring app use the notification listener and the CallScreeningService role without a Call Log or SMS declaration?
6. **Gmail add-on vs Gmail API.** Does an add-on with the sensitive-only scope avoid CASA while still giving per-message analysis on mobile Gmail?
7. **ScreenCaptureKit on iOS 27.** Can it replace ReplayKit for a user-started "check my screen" session?
8. **LiveAssistance (FaceTime).** Do eligibility rules permit a "trusted contact joins the call" assistance use case?

Flag for the safety researcher (not resolved here): UK lawfulness of recording, transcribing or analysing calls routed through a Twilio number, and of notifying a third-party caregiver about an adult's communications (consent, UK GDPR lawful basis, capacity). Twilio's AI legal notice on Real-Time Transcription is relevant: [Twilio: `<Transcription>`](https://www.twilio.com/docs/voice/twiml/transcription).

### Gaps
- No official latency figures for Gemini or Twilio transcription were found.
- No Apple doc covering App Review treatment of server-side alerting from Message Filter queries was found.
